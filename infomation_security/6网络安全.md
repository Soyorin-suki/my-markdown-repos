# 网络安全
## ch20 IPSec
虽然对于各种应用都有相应的安全机制，但**仍然需要一种跨协议层**的机制来提供统一的安全服务。IPSec（Internet Protocol Security）就是这样一个协议层，它为IP网络通信提供安全服务。

IPSec提供一种跨局域网，跨网络的安全通信，可以加密/认证IP层上的所有流量。

- VPN(Virtual Private Network)就是IPSec的一个重要应用。VPN利用公共网络来构建私人专用网络，称为虚拟私有网络（跨公网组建私有网络）。
- IPSec(IP Security),是一组开放协议的总称。定义了保护数据私密性，保证数据安全性，确保数据合法性，抗重放的方法。
- IPSec提供的安全服务：
  - 数据加密：通过数据加密保证机密性。
  - 数据完整性验证：通过数据完整性验证确保数据未被篡改。
  - 数据源验证：通过数据源验证确保数据来自合法的发送方。
  - 防止数据重放：通过在接收方拒绝重复的数据包防止恶意用户通过重复发送捕获的数据包进行攻击
- 优点：
  - 当防火墙或路由器使用IPSec时，能够对通过边界的所有流量提供保护，而公司内部或工作组内部的用户则没有安全开销
  - 防火墙内部的IPSec能阻止所有外部流量的旁路，因为防火墙是从互联网进入组织内部的唯一通道
  - 位于传输层(TCP,UDP)之下的IPSec对应用层是透明的
  - IPSec可以对终端用户透明。

### IPSec体系结构
IPSec不是一个单独的协议，IPSec VPN体系结构主要用三个协议去创建安全架构。
1. IKE(Internet Key Exchange, 互联网密钥交换)：它的对象是密钥。为IPSec提供了自动协商交换密钥、建立安全关联，通过数据交换来计算密钥。
2. ESP(Encapsulating Security Payload, 封装安全载荷)：它的对象是用户数据。对用户的数据进行封装，提供对数据进行认证和加密，使用**IP协议号50**
3. AH(Authentication Header, 认证头)：它的对象是用户数据。提供对数据进行认证，不加密，使用**IP协议号51**

### 安全关联SA(Security Association)
- 用IPSec保护一个数据包前，必须先建立一个安全关联(IPSec SA)
- SA是一组规则，定义了IPSec对等体间将使用的数据封装模式(AH或ESP)，验证算法，加密算法，密钥等参数。
- 安全关联是单向的，因此两个对等体间通信需要至少两个安全关联。
- 建立SA的方式：
  - 手工配置：管理员在每个对等体上手工配置SA参数，适用于小规模网络。
  - 自动协商：使用IKE协议自动协商SA参数，适用于中大规模的动态网络。

### 安全关联
- SA由三个参数唯一标识：
  - 安全参数索引(Security Parameter Index, SPI)：一个32位的值，由发送方生成，标识一个特定的SA。
  - 目的IP地址：SA的目的IP地址。
  - 安全协议号：标识使用的安全协议（AH(50)或ESP(51)）。
- 安全关联数据库(SAD)
- 定义了每个SA的相关参数

### AH
AH提供的安全服务：
- 无连接数据完整性
- 数据源认证
- 抗重放服务
- 支持两种模式：
  - 传输模式(Transport Mode)：AH头直接跟在IP头后面，保护IP数据包的有效载荷。
  - 隧道模式(Tunnel Mode)：AH头和一个新的IP头一起封装整个原始IP数据包，保护整个数据包。
AH不提供保密性服务；它不加密所保护的数据包

IP报头|AH报头|IP payload

下一头部|负载长度|保留|安全参数索引(SPI)|序列号|认证数据

- 下一头部：8位，标识AH头后面的协议类型（如TCP、UDP等）
- 负载长度：8位，表示AH头的长度，以32位字为单位，不包括前8字节
- 保留：16位，保留字段，必须设置为0
- 安全参数索引(SPI)：32位，由发送方生成，标识一个特定的SA，只有逻辑意义
- 序列号：32位，单调递增的序列号，用于防止重放攻击
- 认证数据：可变长度，包含对AH头和IP数据包进行认证的结果


### ESP
ESP提供的安全服务：
- 无连接数据完整性
- 数据源认证
- 抗重放服务
- 数据保密
- 有限的数据流保护

保密通过使用密码算法加密IP数据包的相关部分来实现

IP报头|ESP报头|IP payload|ESP尾部|ESP认证数据

安全参数索引(SPI)|序列号|负载数据|填充|填充头部|下一个头部|认证数据

- 安全参数索引(SPI)：32位，由发送方生成，标识一个特定的SA，只有逻辑意义
- 序列号：32位，单调递增的序列号，用于防止重放攻击，SA建立之初为0
- 负载数据：包含由下一头部字段给出的变长数据
- 填充：0-255字节的填充数据，确保负载数据的长度是4字节的倍数
- 填充头部：8位，表示填充数据的长度
- 下一个头部：8位，标识ESP尾部后面的协议类型（如TCP、UDP等）
- 认证数据：可变长度，包含对ESP头和IP数据包进行认证

### TCP/IP协议中安全机制的位置
|网络层|传输层|应用层|
|---|---|---|
|IPSec|SSL/TLS|SSH,HTTPS,SMTP等|
|它对终端用户和应用是透明的|可以作为潜在的协议透明使用，也可以在特定包中使用|特定应用协议的安全机制|
|在TCP下面|在TCP上面，HTTP/FTP等下面|在HTTP/FTP等上面|

### 传输层安全TLS(Transport Layer Security)
- TLS是安全服务中应用最广泛的Internet标准
- TLS在SSL的基础上发展而来，并逐步取代了SSL
- TLS为TCP提供了端到端的安全服务
- TLS是两层协议
