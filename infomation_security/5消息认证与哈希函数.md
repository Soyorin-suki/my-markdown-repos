## ch11 hash函数
加密与认证是不同的安全机制，也是不同的安全服务：

认证交换是通过信息交换来保证实体身份的真实性；使用一些安全机制，保证通信实体是他所声称的实体。

数据源认证：保证收到的消息确实来自于声称的发送者。

提供认证服务的算法--产生认证符的算法，应该具有的属性：
- 与被认证的实体的身份相关
- 可验证

非对称加密中的A->B E(PR_A,M)就是认证符，B可以用PU_A验证。

### 数据完整性服务
保证收到数据的确是授权实体发出的数据。
1. 数据源的认证
2. 数据本身的完整性
认证符的作用：
1. 用于身份认证
2. 用于数据完整性证明

### hash函数
1. 单向函数
2. 任意长输入，固定长输出
3. 抗碰撞：很难找到两个不同的输入得到相同的输出
要求：
1. 抗原像攻击：给定一个输出，找到一个输入使得hash函数的输出等于该输出计算上是不可行的。
2. 抗弱碰撞攻击：给定一个输入，找到另一个输入使得hash函数的输出相同计算上是不可行的。
3. 抗强碰撞攻击：找到任意两个输入使得hash函数的输出相同计算上是不可行的。
4. 伪随机性：H的输出满足伪随机性测试标准

### 迭代散列函数
- 把原始消息M分成长度为b的块，最后一个分块不足b位则进行填充
- 设定初始值$CV_0=IV$
- 压缩函数f,$CV_i=f(CV_{i-1},M_i)$
- 最后一个$CV_i$即为hash值

### 应用中对认证的需求
网络通信中面临的攻击：
1. 消息泄露
2. 传输分析
3. 伪装
4. 内容修改
5. 消息延时或重放
6. 发送方否认
7. 接收方否认
对抗以上攻击，需要哪种安全机制？
1，2需要消息保密，3，4，5需要消息认证，6需要数字签名，7需要数字签名+协议

### 产生认证符的算法
1. 单向压缩函数-hash函数
2. 消息认证码message authentication code (MAC)
使用对称密钥，把任意长的消息变成定长的认证符

基于DES的MAC算法：CBC-MAC：\
按照CBC求一次DES加密，最后一次加密的输出就是MAC值

用MAC，将认证与加密分离，使层次结构更加灵活，便于适应各种应用。


## ch13 数字签名
数字签名是一种新的安全机制\
数字签名=认证+仲裁

例如：A-->B ，A产生订单，B发货，A拒绝付款，AB产生矛盾，需要第三方仲裁。

### 对数字签名的要求
1. 认证功能
   1. 方便确定数据源--身份认证
   2. 对数据的完整性进行检验
2. 必须能被第三方仲裁
3. 必须能被验证
4. 产生、识别、验证数字签名比较容易，保存副本可行

### 经典的数字签名
1. RSA数字签名
2. DSA数字签名（DSS是标准，DSA是算法）

### 直接数字签名DDS
DDS指只涉及通信双方的数字签名
- 弱点：发送方可以否认发送了消息（称私钥被盗等）
- 解决方法：1. 签名中加入时间戳，2. 密钥泄露后立刻向管理中心报告。
- 威胁：攻击者获取密钥后可以伪造时间戳发送

### 仲裁数字签名ADS
- 引入仲裁者A：
  - 验证签名的消息
  - 加入时间戳
