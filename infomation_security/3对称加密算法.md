# 对称加密算法

## ch4 分组密码和数据加密标准DES
### 流密码与分组密码
流密码：每次加密数据流的一位或一个字节，需要位流发生器（随机，不可预测）

分组密码：将一个明文分组作为整体加密，得到与明文等长的密文分组。分组加密方式。

分组密码的应用比流密码要广泛。

### feistel密码结构
分组密码的分组长度n决定了可能的明密文分组共有$2^n$种，加密过程必须可逆决定了双射函数的总数为$2^n!$(密钥空间)。

#### feistel密码
- 扩散：是明文的统计特征消散在密文中，可以通过让明文尽可能多的影响多个密文来实现
- 混淆：即使获得了密文与明文，也无法求出密钥，可以通过一些非线性的算法来实现。

大部分分组密码都采用了feistel结构，包括数据加密标准DES。优点是加密和解密操作非常相似，且可以使用相同的算法实现。

结构参数与特征：
- 分组长度：分组长度越长，安全性越高，但加密效率越低。
  - block size: 64(常用)，128(AES)
- 密钥长度：密钥长度较长，安全性越高，但加密效率越低。
  - key size: 56(常用)，128(AES)
- 迭代轮数：Feistel密码的本质在于单轮不能提供足够的安全性，需要多轮迭代来增强安全性。
  - rounds: 16(常用)，10(AES)
- 子密钥产生算法
- 轮函数

### 数据加密标准DES(data encryption standard)
DES算法是一种通过56bit密钥对64bit数据块进行加密的分组密码算法，采用了16轮Feistel结构。

DES算法：
- 分组长度：64bit
- 密钥长度：64bit，其中8bit用于奇偶校验，实际密钥长度为56bit
- 算法主要包括：
  - 初始置换IP
  - 16轮迭代的乘积变换
  - 逆初始变换$IP^{-1}$
  - 子密钥产生器

初始置换IP与逆初始置换$IP^{-1}$是为了方便早期的硬件实现，并不增加安全性。

每轮变换按照Feistel结构进行：
$$L_i=R_{i-1}, \quad R_i=L_{i-1}\oplus F(R_{i-1},K_i)$$
其中轮函数F由四部分组成：
- 扩展置换E：将32bit的输入扩展为48bit
- 异或xor：将扩展后的输入与48bit的子密钥进行异或运算
- S盒替代：将48bit的输入分成8组，每组6bit，经过S盒替代后得到32bit的输出
- P盒置换：对S盒的输出进行置换，得到最终的32bit输出

密钥生成算法：轮密钥48位

大概就是R首先经过扩展置换E变成48bit，然后与子密钥K_i进行异或运算，得到48bit的结果，再经过S盒替代和P盒置换得到32bit的输出

扩展置换：在密码学上，输入的一位将影响两个替代，所以输出对输入的依赖性将传播的更快。这是雪崩效应。

### DES的强度 - key size
评价为key有点短。

多重DES：使用多个DES算法进行加密，增加密钥长度，提高安全性。常见的有2DES和3DES。

双密钥三重DES(EDE)：使用两个密钥进行三重DES加密，密钥长度为112bit。

## ch6 高级加密标准AES(advanced encryption standard)
采用了Rijndael算法。
### Rijndael算法
- 不属于Feistel结构，而是一种替代-置换网络结构(SPN)，具有更高的安全性和效率。
- 加密，解密相似但不对称
- 明文分组支持128, 192, 256 bit
- 密钥长度支持128, 192, 256 bit
- 有较好的数学理论基础
- 结构简单，速度快
- 设计上能抵抗所有已知的攻击方法

通常包括10轮，每轮包括以下步骤：
1. 字节替代(SubBytes)：使用S盒对每个字节进行替代
2. 行移位(ShiftRows)：对状态矩阵的行进行循环左移
3. 列混淆(MixColumns)：对状态矩阵的列进行线性变换
4. 轮密钥加(RoundKeyAdd)：将状态矩阵与轮密钥进行异或运算（这是唯一用到密钥的步骤）

最后一轮不进行列混淆。


## ch7 分组加密的工作模式
1. Electronic CodeBook(ECB)电码本模式
2. Cipher Block Chaining(CBC)密码分组链接模式
3. Cipher Feedback(CFB)密码反馈模式
4. Output Feedback(OFB)输出反馈模式
5. Counter(CTR)计数器模式

### ECB模式
- 一次处理一组明文分块，每次使用相同的密钥加密。
- 每一个分组的加密都独立于其他分组
- 加密: $C_i=E_K(P_i)$
- 解密: $P_i=D_K(C_i)$
- 用于数据较小的情况，比如加密秘钥
- 优点：简单，易于实现
- 缺点：相同的明文分组会得到相同的密文

### CBC模式
为了客服ECB模式的缺点，引入了一个初始向量IV。
- 加密: $C_i=E_K(P_i\oplus C_{i-1})$，其中$C_0=IV$
- 解密: $P_i=D_K(C_i)\oplus C_{i-1}$，其中$C_0=IV$
- 优点：相同的明文分组会得到不同的密文，增加了安全性
- 缺点：加密和解密过程不能并行，IV必须是随机的且唯一的
- 具有有限的错误传播能力
- 具有自同步功能

### CFB模式
若待加密消息需要按照字符、字节或比特处理时，使用CFB模式。
并称待加密消息按r比特处理的CFB模式为CFB-r模式。

适用范围：
- AES-128/192/256
- 数据库加密要求加密时不能改变明文的字节长度，因此适合使用CFB模式。

加密：
1. 初始状态：$C_0=IV$
2. 加密寄存器内容：$R_i=C_{i-1}$
3. 取位与异或：$C_i=E_K(R_i)\oplus P_i$
4. 反馈更新：$R_{i+1}=(R_i<<r)|C_i$
5. 循环上述步骤

解密：
- 与加密过程相似，但反馈更新不同：$R_{i+1}=(R_i<<r)|C_i$

有限的错误传播能力。

### OFB模式
与CFB模式类似，但反馈更新不同：$R_{i+1}=E_K(R_i)$，不受明文和密文的影响。
- 相同明文：与CBC和CFB一样，相同明文输入得到不同密文输出
- 链接依赖性：密钥流是独立于明文的（具有典型流密码的结构）
- 错误传播：一个或多个比特错误的任一密文字符仅会影响一个明文字符的解密
- 错误恢复：OFB能够从密文比特错误中恢复，但是如果丢失一个或多个密文字符，解密器将无法恢复。

### CTR模式
类似OFB模式，但加密的是计数器的值。

特点：
- 可并行加密和解密
- 预处理
- 吞吐量仅受并行处理能力的限制
- 随机访问能力
- 可证明安全
- 简单性（只要求实现加密算法）
- 密钥/计数器T不能重用

## ch8 伪随机数的产生和流密码
大量的基于密码学的网络安全算法和协议都使用了二进制随机数
- 密钥分发和相互认证方案
- 会话秘钥的产生
- RSA公钥的产生
- 对称加密的流密码

随机性与不可预测性！

随机数的产生
- 真随机数发生器(TRNG)/非确定性随机数发生器(NRNG)：利用物理源来产生随机位串
- 伪随机数发生器(PRNG)/确定性随机数发生器(DRNG)：使用算法来产生随机位串，输入一个随机种子，输出一个伪随机数序列。

PRNG的基本原则：
- 分布均匀性：输出的随机数应该在其范围内均匀分布。
- 不可预测性：给定输出的随机数序列，无法预测下一个随机数。

### 流密码stream cipher
- 按位或按字节加密数据流的对称加密算法。
- 能产生伪随机密钥流keystream和明文进行xor
- 加密: $C_i=P_i\oplus K_i$
- 解密: $P_i=C_i\oplus K_i$
- 优点：加密效率高，适合加密大数据流
- 缺点：密钥流必须是随机的且不可预测的，密钥流的重用会导致安全问题（如双重加密攻击）

流密码适合处理数据流：数据通信信道或网页浏览连接；
分组密码适合处理数据块：文件传输，email和数据库.
